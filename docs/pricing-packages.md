# بستهٔ پیشنهادی و جمع‌آوری قیمت

این نسخه موتور قطعی `packages-1.1.0` دارد. اپلیکیشن روی Windows و loopback باقی می‌ماند. فقط worker دریافت عمومی قیمت و پایش اختصاصی آن روی `xdo-new` نصب شده‌اند. در این تغییر هیچ تستی نوشته یا اجرا نشده است؛ unit، integration، E2E، browser journey و `npm run verify` همگی طبق درخواست کاربر ممنوع‌اند. بررسی سورس عمومی ارائه‌دهنده، syntax و اعتبارسنجی ضروری پیکربندی زیرساخت انجام شده است؛ هیچ نشست/پروژه/رویداد آزمایشی محصول ساخته نشده است.

## اجرا و دسترسی

تونل موجود `scripts/tunnel.ps1` را فعال نگه دارید و با `npm start` اپلیکیشن را اجرا کنید. اگر نسخهٔ قبلی برنامه در حال اجراست، پس از تغییر سورس و `.env` آن را بازراه‌اندازی کنید. ورود عادی با `LOCAL_ACCESS_TOKEN` است. برای پنل «مدیریت جمع‌آوری قیمت» با `ADMIN_ACCESS_TOKEN` در `.env` خصوصی وارد شوید یا از دکمهٔ «ورود به حالت مدیر» بالای صفحه و همان کلید استفاده کنید؛ مقدار کلید در خروجی، Git یا bundle مرورگر قرار نگرفته است. نشست‌های قبلی خودکار نقش مدیر نمی‌گیرند. تغییر حالت مدیر/کاربر روی همان نشست انجام می‌شود و پروژه‌های ذخیره‌شده را حفظ می‌کند؛ صفحه بازخوانی و فرم ذخیره‌نشده پاک می‌شود. بازگشت به حالت کاربر بدون کلید، دسترسی مدیریت را سمت سرور قطع می‌کند. دکمهٔ خروج پس از توضیح محدودیت فضای کاری، نشست را منقضی و کوکی را پاک می‌کند؛ رکوردها حذف نمی‌شوند. هر ورود تازه مانند نسخهٔ قبلی workspace مستقل دارد و به پروژه‌های نشست قبلی دسترسی ندارد؛ این سیستم هویت تولیدی نیست. migration `005_session_controls.sql` فقط مجوز UPDATE ستون‌های `role` و `expires_at` جدول نشست را به نقش برنامه می‌دهد؛ پس از بکاپ با `npm run migrate` اعمال شود.

تنظیمات جدید اتصال مدیریت `PRICING_ADMIN_DATABASE_URL` با نقش جدا و محدود است. برای بازسازی تنظیمات روی همین محیط: `python scripts/configure-pricing-local.py`، که فقط کلیدهای غایب را به فایل ignored اضافه می‌کند. URL دلخواه یا فرمان اجرایی از API مدیریت پذیرفته نمی‌شود. اجرای دستی برای هر منبع ده دقیقه و برای هر مدیر یک دقیقه فاصله دارد؛ فقط منبع فعال و دارای adapter قابل صف‌گذاری است.

## قواعد تصمیم

| شناسه | تصمیم |
|---|---|
| RUN-001 | بدون تأیید توان عملیات، PaaS ترجیح دارد؛ تیم دارای DevOps و توان نگهداری سرور/DB می‌تواند VM مشترک را بررسی کند. اجارهٔ VM حذف نمی‌شود. |
| DB-001 | DB مدیریت‌شده کنار PaaS؛ DB مشترک در IaaS فقط با مسئولیت عملیاتی تیم. |
| GIT-001 | Git خصوصی دلیل سرور مستقل نیست؛ الزام کنترل یا محدودیت دسترسی/میزبانی مستقل بررسی می‌شود. |
| CI-001 | Git hosting و runner مستقل‌اند؛ runner خصوصی روی ماشین برنامه تجمیع نمی‌شود. |
| MEDIA-001 | دیسک مشترک فقط برای دادهٔ قابل جایگزینی و حجم سه‌ماهه حداکثر ۱۰GB؛ در سایر حالت‌ها فضای مستقل بررسی می‌شود. |
| LOG-001 | ابتدا کفایت لاگ PaaS نسبت به retention/جست‌وجو؛ خرید تکراری فقط پس از اعلام ناکافی بودن. |
| CAP-001 | تعداد کاربران ظرفیت قطعی نمی‌دهد؛ بار بزرگ یا دسترس‌پذیری حساس نیازمند طراحی افزونگی است. |
| METERED-001 | برای انتخاب صریح آروان، ساخت پیکربندی مستقل و کنترل حدود منبع پیش از درخواست محاسبه. |
| SUPPORT-001 | فقط سطح پشتیبانی منتخب؛ دامنه و هزینهٔ قرارداد نیازمند استعلام و جدا از زیرساخت. |

منابع اولیهٔ پلن ثابت، فرض ظرفیت‌اند و تضمین عملکرد نیستند. قیمت stale بیش از هفت روز، ناموجود، قیمت «شروع از» یا منطقهٔ غیرایران به پلن قطعی تبدیل نمی‌شود. گزارش یک بستهٔ منتخب و حداکثر یک جایگزین معماری دارد. Git، CI، بکاپ، مالیات، ترافیک یا نگهداری فاقد قیمت، ناموجود می‌مانند. اجزای مشترک دوباره جمع نمی‌شوند. بیشتر بودن جمع معلوم از بودجه صریحاً ناکافی اعلام می‌شود؛ کمتر بودن آن، کفایت هزینهٔ کامل را اثبات نمی‌کند.

## تعرفه، پیکربندی و برآورد

`fixed_plan` منابع و مبلغ همان پلن را نگه می‌دارد. `metered` مشخصات منبع، منطقه، کلاس، واحد، روش محاسبه و حدود اعلام‌شده را نگه می‌دارد؛ اگر نرخ منتشر نشده، `rate=null` است. `pricing.versions` تاریخچهٔ immutable محتوای تعرفه است و `pricing.estimates` تاریخچهٔ مستقل پیکربندی و نتیجهٔ محاسبه. انتشار جدید گزارش قدیمی را تغییر نمی‌دهد؛ snapshot قواعد، کاتالوگ و بسته در `app.reports` باقی می‌ماند. گزارش‌های پیشین هنگام migration حفظ شده‌اند. دیدن نسخهٔ تاریخی به‌خودی‌خود هیچ رویداد فعالیت مصنوعی تولید نمی‌کند.

محاسبات مبلغ با decimal مبتنی بر BigInt و رشته‌های اصلی انجام می‌شوند؛ گردکردن فقط در نمایش است. `sourceTotal` مبلغی است که API برای یک نمونهٔ صریح برگردانده؛ `sourceTotalForInstances` ضرب همان مبلغ در تعداد نمونه‌ها طبق منطق منتشرشدهٔ ماشین‌حساب است. `calculatedTotal` جمع ردیف‌ها با تعداد نمونه و `difference` اختلاف دو جمع قابل مقایسه است. اختلاف غیرصفر برای بررسی نگه داشته می‌شود و بی‌دلیل به گردکردن نسبت داده نمی‌شود. مقدار `unitPrices[].amount` آروان جمع همان پله/ردیف است؛ نرخ هر GB یا CPU از آن استخراج نمی‌شود. `from/to/used` شاهد همان پاسخ است، نه اثبات خطی‌بودن یا جدول نرخ عمومی. اصل ریال محفوظ است؛ تومان فقط تقسیم بر ۱۰ است.

مقدار CPU، RAM، دیسک پایدار، دیسک موقت کانتینر، IP، منطقه، ترافیک دریافتی/ارسالی، مدت و تعداد نمونه‌ها از فرم همین درخواست می‌آید. هیچ default ماشین‌حساب یا حساب کاربر خوانده نمی‌شود. مقادیر CPU و RAM از یک خانواده انتخاب می‌شوند؛ حدود و گام‌های موجود در metadata کنترل می‌شوند. صفرِ مقدار انتخابی به‌عنوان نرخ رایگان استنتاج نمی‌شود. بازهٔ ۳۰ روز فقط اگر صریحاً انتخاب شده باشد مبنای مقایسه با بودجهٔ ماهانه است؛ هزینهٔ سایر بازه‌ها «ماهانه» نیست.

## وضعیت واقعی adapterها

**لیارا:** منبع [صفحهٔ رسمی قیمت](https://liara.ir/pricing/)، parser `liara-ssr-1.0.0`. HTML رسمی سمت سرور برای PaaS پایه، DBaaS پایه، IaaS و مقدار نمایان Object Storage parse می‌شود. دریافت اولیهٔ سرویس نصب‌شده ۲۱ رکورد منتشر کرد: ۷ برنامه، ۷ دیتابیس، ۶ ماشین و یک فضای فایل. مبالغ ماهانه و ساعتی مستقل‌اند؛ IP و ترافیک ماشین جداست. نام مشترک سیاره‌ها با نوع سرویس/منطقه/دوره/سطح برخورد ندارد. سطوح نقره‌ای/طلایی و مقادیر دیگر slider فضای فایل خارج از پوشش فعلی‌اند؛ از مقدار نمایان ۲۰GB نرخ خطی استخراج نشده است.

**آروان:** [ماشین‌حساب رسمی](https://panel.arvancloud.ir/calculator) یک shell ماژولی است. `CALCULATOR_REMOTE` به `https://calculator.panel.arvancloud.ir/remoteEntry.js` اشاره می‌کند. در chunk منتشرشدهٔ نسخهٔ `calculator-mfe@3.0.1`، درخواست‌های بدون احراز هویت به این دو endpoint شناسایی شد؛ endpoint حدس زده نشده است:

- دریافت مشخصات: `GET https://napi.arvancloud.ir/alak/v1/calculator-settings`
- محاسبهٔ همان پیکربندی: `POST https://napi.arvancloud.ir/chortke/v1/calculate-resources`

parser `arvan-calculator-1.0.0` مشخصات IaaS، کانتینر و DevOps را استخراج می‌کند. دریافت اولیهٔ worker سه سند metadata منتشر کرد. `last_success` و سن داده برای این منبع به مشخصات تعرفه مربوط است، نه تأیید نرخ واحد. API تنظیمات نرخ واحد، جدول کامل سهمیهٔ رایگان، SLA مدیریت یا تمام ترکیب‌های قابل سفارش را اعلام نمی‌کند؛ این‌ها ناموجود/نیازمند تأیید می‌مانند. محاسبهٔ واقعی کاربر در اپلیکیشن محلی با URL ثابت، timeout، سقف پاسخ، کنترل تطبیق منابع و محدودیت نرخ انجام و روی DB سرور ذخیره می‌شود. درخواست محاسبه retry خودکار ندارد تا بار تکراری ایجاد نکند. دریافت روزانهٔ metadata مستقل از سیستم توسعه است؛ برآورد نیازمند درخواست کاربر و روشن بودن اپلیکیشن محلی است.

**۱۵ ارائه‌دهندهٔ دیگر:** همهٔ منابع کاتالوگ ثبت شده‌اند؛ adapter استخراج خودکار ندارند و غیرفعال‌اند. شواهد دستی قدیمی با تاریخ واقعی خود محفوظ‌اند. دریافت سادهٔ صفحه موفقیت استخراج قیمت اعلام نشده است.

## زیرساخت و عملیات

منابع نصب‌شده: schema `pricing` در DB `torob_cloud`، نقش‌های `torob_price_worker` و `torob_price_admin`، کاربر سیستم `torob-pricing`، سرویس `torob-cloud-pricing.service` و dashboard `torob-pricing` در پوشهٔ مدیر ترب. worker روی loopback سرور به DB متصل است؛ هیچ listener عمومی ندارد. مجوز shell/Docker، دسترسی به schema برنامه یا DBهای سایر پروژه‌ها ندارد. سقف حافظه ۱۶۰MiB، CPU پانزده درصد، سه اتصال و timeout SQL پنج ثانیه است.

زمان‌بندی روزانه ۰۳:۱۵ UTC، معادل ۰۶:۴۵ تهران، در DB ثبت و توسط سرویس دائمی systemd اجرا می‌شود؛ بعد از reboot یا downtime، اجرای عقب‌افتاده قابل انجام است. قفل advisory و unique index مانع اجرای تکراری می‌شوند. timeout هر دریافت ۲۰ ثانیه، حداکثر سه تلاش و backoff محدود است. challenge یا redirect غیرمنتظره دور زده نمی‌شود. پاسخ خام پیش از parse ذخیره می‌شود؛ حداکثر ۶MiB هر پاسخ، نگهداری ۳۰ روز و سقف کل ۱۰۰MiB. هش و metadata شواهد و نسخه‌های قیمت حفظ می‌شوند. نسخه‌های diff فعلاً سیاست حذف خودکار ندارند و رشد DB باید پایش شود.

تغییر بیش از ۳۰٪ قیمت، حذف منبع، تغییر مشخصات/هزینهٔ جانبی یا ساختار metadata آروان برای بررسی نگه داشته می‌شود. مدیر تنها همان candidate را تأیید/رد می‌کند؛ اگر نسخهٔ مبنا عوض شده باشد انتشار رد می‌شود. در شکست دریافت یا parse، نسخهٔ معتبر قبلی و تاریخ واقعی آن باقی می‌مانند.

متریک‌های واقعی روی gateway موجود اضافه شده‌اند؛ job و datasource مشترک عوض نشده‌اند. label فقط شناسهٔ محدود ارائه‌دهنده است، نه URL، متن خطا یا شناسهٔ اجرا. تاریخچهٔ بدون اجرا، تعداد پلن و زمان ناموجود را صفر موفق نمایش نمی‌دهد. عنوان dashboard مشخص می‌کند سن دادهٔ آروان سن metadata است. متریک AI ساختگی برای اجرای قواعد ارسال نمی‌شود.

نصب پس از بازبینی و بکاپ scoped انجام شد. بکاپ این نوبت: `/opt/torob-cloud/backups/pricing-20260917T114223595575Z`، همراه dump تازهٔ DB ترب در مسیر backups. فقط قواعد HBA دو نقش ترب اضافه و validate/reload شدند؛ PostgreSQL یا سرویس‌های نامرتبط restart نشدند. Grafana قبل از افزودن dashboard جدید backup شد. پنج dashboard قبلی دست‌نخورده‌اند؛ gateway ترب برای دریافت متریک جدید restart شد.

برای تکرار نصب روی همین سرور، ابتدا inspect و برنامهٔ تغییر scoped را مرور کنید، سپس `node scripts/build-pricing-registry.js` و `python scripts/install-pricing.py`. این اسکریپت migration اختصاصی و artifactهای support را ارسال می‌کند، نه سورس اپلیکیشن. برای توقف جمع‌آوری فقط `torob-cloud-pricing.service` را متوقف/غیرفعال کنید؛ داده‌ها و بکاپ‌ها حفظ شوند. بازگردانی config مشترک کامل روی تغییرات جدید دیگران مجاز نیست؛ فقط بخش ترب مقایسه و برگردانده شود.

## محدودیت پذیرش

تست‌های محصول اجرا نشده‌اند. صحت مسیر UI، انتخاب‌ها، محدودیت نقش‌ها و پذیرش نهایی باید توسط کاربر بررسی شود. قیمت عمومی تضمین موجودی یا قابلیت سفارش نیست. سازگاری کامل کلاس CPU/RAM، managed capabilities کانتینر، قرارداد پشتیبانی، قیمت خدمات بدون نرخ و بکاپ خارج از سرور همچنان نیازمند تأییدند. هیچ دادهٔ ارسالی تأییدنشدهٔ کاربر به‌عنوان نرخ زنده منتشر نشده است.


## فرم کوتاه‌تر و بودجهٔ بازه‌ای

فرم اصلی ده فیلد دارد: نام، شرح، فناوری، دیتابیس، توان نگهداری تیم، بازهٔ بودجه، مرحلهٔ پروژه، اهمیت دسترس‌پذیری، نوع فایل و اهمیت فایل. سه سؤال DevOps/سرور/دیتابیس و سؤال قدیمی توان تیم در یک سؤال `operationsCapability` ادغام شده‌اند. نرخ درخواست، هم‌زمانی، حجم لاگ، ارزیابی لاگ PaaS، محل میزبانی و کنترل جزئی Git از فرم حذف شده‌اند. حجم و رشد فایل، retention لاگ، Git مستقل، CI و انتخاب اختصاصی ارائه‌دهنده در بخش بستهٔ «نیازهای تکمیلی» قرار دارند. پیکربندی دقیق آروان فقط با انتخاب صریح آن سرویس نمایش و ارسال می‌شود.

بودجه با `budgetRange` ذخیره می‌شود: زیر ۲ میلیون، ۲ تا ۵ میلیون، ۵ تا ۱۰ میلیون، ۱۰ میلیون به بالا و نمی‌دانم. بازه به مبلغ ساختگی یا نقطهٔ میانی تبدیل نمی‌شود. هزینهٔ معلوم برابر یا بیشتر از ۲ میلیون برای «زیر ۲ میلیون» ناکافی است؛ برای دو بازهٔ میانی، فقط بیشتر شدن از سقف بازه ناکافی بودن را قطعی می‌کند. پایین‌تر بودن هزینه از سقف به معنی تأیید هزینهٔ کامل نیست. بازهٔ آخر سقف نامعلوم دارد و بودجهٔ نامحدود فرض نمی‌شود. منطق یکسان برای بستهٔ ثابت و برآورد ۳۰روزهٔ آروان استفاده می‌شود.

گزارش‌های ذخیره‌شده بازنویسی نمی‌شوند. هنگام بازکردن پروژهٔ قدیمی، بودجهٔ دستی برای ویرایش در بازهٔ مربوط نمایش داده می‌شود و پاسخ‌های عملیاتی قبلی به سؤال واحد نگاشت می‌شوند. اطلاعات تازه فقط پس از ارسال فرم در گزارش جدید ثبت خواهد شد. این تغییر صرفاً با بازبینی سورس و بررسی syntax ارزیابی شده؛ هیچ تست محصولی اجرا نشده است.
